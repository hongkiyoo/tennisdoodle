TennisDoodle

파트너와 코트 그림을 같이 보며 작전을 짜는 iPhone용 웹앱. 화면 전체가 코트이고, 손가락으로 선수와 공을 끌어 옮기며 이야기합니다.

  • 누가복식 파트너, 레슨 코치와 학생, 동호회 친구
  • 언제경기 사이 휴식, 체인지오버 90초, 레슨 전후. 한 폰을 둘이 같이 보는 상황이 기본
  • 핵심 동작단식(2명)·복식(4명) 전환, 선수·공 드래그, 기본 포메이션 불러오기, 되돌리기
  • 형태Safari에서 열고 ‘홈 화면에 추가’하면 앱처럼 전체 화면으로 실행되는 PWA. 앱스토어 심사 없음

오른쪽 목업은 실제로 만질 수 있습니다. 선수나 공을 끌어 보세요. 휴대폰으로 이 페이지를 열면 두 손가락으로 두 선수를 동시에 옮길 수도 있습니다.

코트는 실제 치수로 그린다

좌표를 픽셀이 아니라 미터 단위로 잡고, 네트 중앙을 원점 (0, 0)으로 둡니다. SVG의 viewBox가 미터→화면 변환을 맡으므로 어떤 아이폰에서든 비율이 정확하고, 나중에 “네트에서 3 m” 같은 거리 표시도 그대로 쓸 수 있습니다.

세로 화면에 코트가 꼭 맞는다

복식 코트에 앞뒤 1.5 m, 좌우 0.8 m 정도 여유를 두면 세로:가로가 약 2.0~2.2:1입니다. 최근 아이폰 세로 화면(약 2.17:1)과 거의 같아서 세로 고정이 가장 자연스럽습니다. 남는 공간은 코트 바깥 색으로 채우고, 비율은 preserveAspectRatio="xMidYMid meet"로 맞춥니다.

손가락 하나로 끝나는 조작

코트 위에서 쓰는 앱이라 땀 묻은 손, 햇빛, 짧은 휴식 시간을 전제로 합니다. 정밀함보다 크게 잡히고 빨리 움직이는 쪽을 택합니다.

제스처동작설계 메모
토큰 누르고 끌기선수/공 이동보이는 원은 작아도 터치 영역은 지름 44pt 이상(Apple HIG). 누르는 순간 1.35배 커지고 그림자가 생겨 “집었다”는 느낌을 줌
두 손가락으로 각각 끌기두 토큰 동시 이동Pointer Events의 pointerId별로 따로 추적. 나와 파트너가 한 화면에서 동시에 움직일 수 있음
손가락이 토큰을 벗어남계속 끌림setPointerCapture로 빠르게 움직여도 놓치지 않음
손가락에 가려짐위치 확인끄는 동안 “네트에서 3.2 m · 오른쪽 1.1 m” 말풍선을 손가락 위쪽에 표시
화면 밖으로 끌기가장자리에서 멈춤코트 바깥 여유 공간까지는 허용, 화면 밖은 막음
되돌리기 버튼직전 상태로드래그 한 번 = 기록 한 칸. 최대 50단계
빈 코트 끌기MVP에선 아무 동작 없음v0.2 그리기 모드에서는 화살표 그리기. 확대/스크롤은 막음
기본 자료 · 복식 포메이션

시작점이 되는 다섯 가지 배치

작전 이야기는 대개 정해진 포메이션에서 출발합니다. 포메이션 버튼으로 바로 불러오고, 거기서 끌어 옮기며 변형합니다. 모두 우리 팀(주황, 아래)이 듀스 코트에서 서브하는 장면입니다. ‘데모에 적용’을 누르면 위 목업에 반영됩니다.

기술 설계

가볍게, 오프라인으로

코트장엔 와이파이가 없을 때가 많습니다. 서버 없이 정적 파일만으로 동작하고, 한 번 열면 오프라인에서도 켜지게 만듭니다.

스택 제안

  • Vite + TypeScript, 프레임워크 없이 시작. 화면 요소가 적어 React까지는 필요 없음
  • SVG로 코트와 토큰 렌더링. 객체가 5~6개뿐이라 Canvas보다 단순하고 어떤 해상도에서도 선명
  • Pointer Events로 터치·마우스 통합 처리
  • PWA: manifest.json(display: standalone), 서비스 워커로 오프라인 캐시, apple-touch-icon 180×180
  • 저장: localStorage (장면 목록) v0.2
  • 배포: GitHub Pages 또는 Vercel (PWA는 HTTPS 필수)

iOS Safari에서 챙길 것

  • 보드에 touch-action: none — 끄는 동안 페이지 스크롤·확대 방지. iOS는 user-scalable=no를 무시하므로 이게 핵심
  • overscroll-behavior: none + 화면 고정 레이아웃 — 고무줄 튕김 방지
  • -webkit-touch-callout: none, user-select: none — 길게 눌렀을 때 메뉴·텍스트 선택 방지
  • viewport-fit=cover + env(safe-area-inset-*) — 다이내믹 아일랜드·홈 인디케이터 피하기
  • 진동(Vibration API) 미지원 → 확대·그림자 같은 시각 피드백으로 대신
  • Screen Wake Lock API — 이야기하는 동안 화면 꺼짐 방지

데이터 모델 (장면 하나)

좌표는 미터, 원점은 네트 중앙. 아래쪽(+y)이 우리 팀. 이 구조를 그대로 JSON으로 저장하고, 압축해서 공유 링크의 # 뒤에 넣으면 서버 없이 파트너에게 보낼 수 있습니다.

type Team = "A" | "B";            // A = 우리 팀(아래), B = 상대(위)

interface Scene {
  mode: "singles" | "doubles";
  players: { id: "A1" | "A2" | "B1" | "B2"; team: Team;
             x: number; y: number; name?: string }[];   // 단위: m
  ball: { x: number; y: number };
  drawings?: { kind: "move" | "shot"; points: [number, number][] }[];  // v0.2
}

// 예: 기본 서브 포메이션
{ mode: "doubles",
  players: [ { id:"A1", team:"A", x: 1.0, y: 12.3 }, { id:"A2", team:"A", x:-2.6, y: 3.0 },
             { id:"B1", team:"B", x:-3.6, y:-12.2 }, { id:"B2", team:"B", x: 2.2, y:-6.6 } ],
  ball: { x: 1.4, y: 12.0 } }

확인이 필요한 것

만들기 전에 정할 다섯 가지

화면 방향제안: 세로 고정. 코트 비율이 아이폰과 맞고, 한 손으로 들고 보여주기 좋음. 가로는 코트가 작아짐
우리 팀 위치제안: 항상 아래. 내 시점과 화면이 일치. 상대 시점이 필요하면 v0.3의 뒤집기 버튼으로
그리기(화살표)를 MVP에 넣을지제안: v0.2로. 드래그만으로도 위치 이야기는 충분히 되고, 그리기는 모드 전환·지우기 UI가 따라와서 범위가 커짐
파트너와 공유 방식제안: 링크 공유부터. 서버 없이 장면을 URL에 담아 보냄. 실시간 동기화는 실제로 필요해지면
선수 표기제안: 색 + 짧은 라벨(A1/A2/B1/B2)로 시작. 이름 입력은 v0.2. 오른손/왼손 표시가 필요한지도 의견 주세요
